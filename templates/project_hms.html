The platform enforces rigorous role boundaries across 4 core stakeholder portals, each tailored with specialized workflows, interfaces, and contextual processors.

Super Admin

routes.py

  • Inquiry Management: Dedicated inbox for contact messages submitted through the website, with read/unread tracking and direct reply routing.
Doctor Workspace

routes.py

3. Deep-Dive Functional Engines & System Modules

The backbone of CareFlow HMS comprises 10 custom-engineered domain engines designed for high concurrency, deterministic financial calculations, clinical compliance, and zero timezone drift.

1. Concurrency Protection (BookingDayLock)

Uses a database row-level locking table (booking_day_locks) with SELECT ... FOR UPDATE to prevent race conditions during concurrent bookings.

2. Dynamic Slot Interval Generation

Computes slots based on session.start_time, session.end_time, and session.slot_duration_minutes (e.g., 20 minutes: 14:00, 14:20, 14:40).

3. Multi-Patient Capacity Caps

Allows up to max_patients (default: 5) per time slot. Full slots are automatically hidden from self-booking patients.

4. Current-Day Past Slot Filtering

Automatically excludes time slots earlier than or equal to current Asia/Kolkata time (get_ist_time()) for public/patient bookings while preserving assisted receptionist overrides.

⚙️ 02

Engine 2: Sequential Live Queue & Token Tracker

Dynamic wait time formulation & appointment lifecycle state machine
appointments.py
Queue Logic & Token Formulation
  • Sequential Token Assignment: Upon patient arrival, receptionist or doctor marks check-in. The system computes:
    token = max(existing_tokens_for_day) + 1
  • Priority Tokens: Emergency walk-ins or priority patients can be inserted at the top of the queue.
  • Dynamic Wait Time Formula:
    Estimated Wait (mins) = (Tokens Ahead of Patient) × (Doctor Avg Slot Duration)
Lifecycle State Machine
CONFIRMED
CHECKED_IN
WITH_DOCTOR
COMPLETED
Optional terminal states: NO_SHOW, CANCELLED

⚙️ 08

Engine 8: Multichannel Notification Architecture

notifications.py & email_service.py
  • Resend HTTPS API Transport: Production transactional email delivery migrated from blocked SMTP ports to Resend HTTPS REST API. Non-blocking, failure-safe design: website requests never crash or hang if external network issues occur.
  • Dispatched Events: Contact inquiries, doctor approvals, doctor password resets, validity extensions, booking confirmations, and prescription PDF links.
  • SMS Alerts & WhatsApp Integration: Automated SMS alerts for bookings and appointment reminders; automated WhatsApp notifications for queue tokens and prescription PDFs (Enterprise tier).
⚙️ 09

Engine 9: Privacy, Security & 10-Digit Doctor Recovery ID

models.py:750-765
  • 10-Digit Doctor Recovery Identifier: Generated upon admin approval and stored securely. Provides an admin-governed, controlled credential recovery mechanism for doctors who forget credentials. Requires verified matching of doctor email, medical registration number, and recovery identifier before administrator reset.
  • Role-Based Access Control: Custom decorators (@admin_required, @doctor_required, @staff_required, @patient_required) strictly validating user sessions, roles, and active status on every route.
  • Mandatory Password Resets: Forces password updates on first login for temporary administrator-generated passwords.
  • Security Headers & CSRF: Enforces X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN, X-XSS-Protection: 1; mode=block, Referrer-Policy: strict-origin-when-cross-origin, and CSRF tokens across all POST requests.
⚙️ 10

Engine 10: Centralized India Timezone Architecture

time_service.py
  • ZoneInfo Centralization: Standardized on ZoneInfo("Asia/Kolkata") (IST, UTC+5:30) across all business workflows.
  • Storage vs Presentation Fidelity: PostgreSQL timestamp columns store clean, naive UTC (TIMESTAMP WITHOUT TIME ZONE).
  • Business Calculations: Today's clinic queue, doctor metrics, slot boundaries, and staff attendance strictly evaluate get_ist_today() and get_ist_time().
  • Jinja Skew Prevention: UI templates render stored timestamps using |ist_datetime and |ist_date Jinja filters with zero timezone skew across midnight/day boundaries.
